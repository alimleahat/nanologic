# Toolchain decision (Milestone 0)

Decided 30 Oct 2026. Everything below runs **inside the app as WebAssembly or JavaScript**. Students install nothing else: no compiler, no Icarus, no Yosys, no Python.

## Summary

| Job | Tool | How it runs | Licence |
|---|---|---|---|
| Syntax and elaboration errors | Icarus Verilog (`ivlpp` + `ivl`), fork revision `75c777c` | WebAssembly, npm `@veriflow/iverilog-wasm@0.1.4` | GPL-2.0-or-later |
| Testbench simulation + VCD | Icarus Verilog (`vvp`) | same package | GPL-2.0-or-later |
| Synthesis checks, top-level ports | Yosys 0.70 | WebAssembly, npm `@yowasp/yosys@0.70.1258` (YoWASP) | ISC (Yosys), ABC is BSD-style |
| Virtual board | Yosys netlist + NanoLogic's own JavaScript simulator (`app/shared/netsim`) | JavaScript, in a worker thread | ours |
| Synthesisability lint (`#` delays, `initial`, `$display` ...) | NanoLogic (`app/shared/lint.ts`) | JavaScript | ours |

All tool locations and settings are in one module: `app/main/toolchain/config.ts`.

## Option A, as evaluated

### Yosys (YoWASP)
- Works in Node and in Electron's main process with no native code. The same files run on macOS (Apple Silicon and Intel), Windows and Linux.
- Size: about 77 MB on disk (66 MB `.wasm` + 11 MB resources). First run in a session takes about 1 s to compile the WebAssembly; later runs are faster.
- Reference project: reads all 14 modules, elaborates `MainCode`, and correctly reports the latch inferred from the incomplete `case` in `BCD7Seg.v` (a real warning, which Quartus also gives).
- Licence: Yosys is ISC, YoWASP packaging is ISC. Both allow bundling in a closed-source app; keep the licence text (see `docs/licences.md`).

### Icarus Verilog
The spec suggested bundling native `iverilog`/`vvp` per platform. A WebAssembly build exists on npm (`@veriflow/iverilog-wasm`) and was evaluated first because it removes all per-platform binaries:
- Works in Node with no native code; about 3.4 MB.
- **All 14 reference testbenches compile, run and produce a VCD, each in about 0.2 s.**
- `$stop` behaviour: the spec asks for `vvp -n`. The WebAssembly `vvp` cannot be given `-n`, and at `$stop` it reads an empty stdin and **continues** (so testbenches with a free-running clock, like `ClockDivider_tb`, would never end). NanoLogic therefore replaces the `$stop` token with `$finish` in the copy of the sources it simulates (same length, so line numbers do not change). This is exactly what `-n` does. A maximum-simulation-time guard and a wall-clock timeout are also always applied, so nothing can hang.
- Timescale: Icarus defaults to 1 s time units, ModelSim (which the course uses) to 1 ns. NanoLogic compiles a one-line file containing `` `timescale 1ns/1ns `` first, so files without their own `` `timescale `` behave as they do in ModelSim. Files that declare one are unaffected.
- **Licence: GPL-2.0-or-later.** See the risk section below.

### Virtual board simulator
Evaluated **DigitalJS** (BSD-2-Clause) with `yosys2digitaljs`:
- DigitalJS is an event-driven gate/word simulator built around a JointJS/jQuery diagram. It is designed for small teaching circuits and runs at roughly kHz-level clock rates in the browser.
- The reference design divides 50 MHz down to 1 Hz with a 25-bit counter, so one visible tick needs 50 million clock cycles. That is out of reach for DigitalJS.
- It also has no built-in way to override an internal net (needed for the divider bypass), and brings a large UI dependency we would not use.

Decision: **write a small simulator** (`app/shared/netsim/compile.ts`, about 700 lines). Yosys flattens the design and simplifies it to word-level cells (`proc; flatten; memory_map; dffunmap; pmuxtree ...`). NanoLogic then generates straight-line JavaScript for the combinational logic (numbers for signals up to 32 bits, BigInt above) and handles flip-flops, latches and asynchronous resets, including clocks generated by logic (ripple clocks such as `CLK_1Hz`).
- Correctness: a unit test feeds 60 random input vectors to an ALU covering add/sub/mul/div/mod, signed and unsigned compares, shifts, part-selects, reductions and 40-bit (BigInt) arithmetic, and compares every output with Icarus Verilog. All match.
- Speed: about 1.5 million clock cycles per second on the reference design on the cloud machine (expect 2-4x more on an M-series Mac). That is fast but still 50x short of real time for a 50 MHz design, so:
- **Divider bypass**: the user can pick any internal signal (e.g. `clkdiv.CLK_1Hz`) and have the virtual board drive it directly with the board clock, or hold it high (for clock-enable style dividers). The reference project then runs at a true 1 Hz.

### Option B: Verilator
Not evaluated further. Verilator generates C++ that must be compiled on the student's machine, which hard constraint 1 rules out.

## Risks and mitigations

1. **GPL Icarus Verilog in a closed-source app.** Shipping GPL programs alongside proprietary software is normally fine when they run as separate programs ("mere aggregation"): NanoLogic only passes files to Icarus and reads its output, and the WebAssembly runs in its own worker. The obligations are to ship the GPL text and to offer the exact source. The package documents the source revision (`dist/SOURCE.md`); NanoLogic shows the licence in `docs/licences.md` and should include it in the installer's About/licence screen. **Ali should get this confirmed** before any commercial release (e.g. by the university's IP office). If it is a problem, the fallback is to drop Icarus and simulate testbenches by other means (no good fallback exists today, so this matters).
2. **Supply chain.** `@veriflow/iverilog-wasm` is a young package (first published Aug 2026) by a single maintainer. Mitigation: the exact version is pinned and its integrity hash is locked in `package-lock.json`; it was reviewed (runs only WebAssembly in a worker, no network access, no native code); it can be rebuilt from the documented source revision with Emscripten if needed. The wrapper (`app/main/toolchain/iverilog.ts`) is small, so swapping to a self-built WebAssembly or native Icarus later only touches one file.
3. **Download size.** Yosys is 77 MB. Installers will be roughly 150-200 MB. Acceptable for a university app.

## Verification in this repository

- `tests/unit/reference-project.test.ts` is the "toolchain spike" script required by M0. It runs on every CI job (Linux, macOS, Windows):
  - imports the reference project and detects `MainCode` as top level,
  - analyses all 14 modules with no errors,
  - runs each of the 14 testbenches to completion (no hang on `$stop`) and parses the VCD,
  - runs the design on the virtual board with manual pin mapping and the 1 Hz divider bypassed, and checks the lamp sequence red, amber, green, amber, red,
  - checks the simulator manages over 200,000 cycles per second without the bypass.
- `tests/unit/netsim.test.ts` covers the small counter design required by M0 and the Icarus cross-check.
- Run them locally with `npm run spike` (reference project only) or `npm test` (everything).
